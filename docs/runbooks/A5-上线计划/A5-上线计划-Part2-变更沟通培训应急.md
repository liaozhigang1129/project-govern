# §1 变更管理

> **变更管理**（Change Management）= 让组织在"上线这一剧变"中平稳过渡的方法论。
> 三要素：**人**（干系人）+ **信息**（沟通计划）+ **行为**（公告与反馈）。

## §1.1 变更管理总览

### §1.1.1 三大原则

| 原则 | 释义 |
| --- | --- |
| **透明** | 所有变更（计划、决策、风险、回退）必须在 24h 内向相关干系人公开 |
| **及时** | 信息早于动作（培训早于试运行、公告早于切流） |
| **闭环** | 每次公告必有反馈通道；每次反馈必有 Owner + SLA |

### §1.1.2 三大变更类型

| 类型 | 触发 | 影响范围 | 处理 SLA |
| --- | --- | --- | --- |
| **重大变更（M-Major）** | 计划外回退、上线日延后、范围变更 | 全员 / 多 BU | 4h 通报 + 高管会商 |
| **中等变更（M-Medium）** | 决策门 No-Go、关键路径延期 | 试点 / 单 BU + PMO | 24h 通报 + PMO 会商 |
| **微小变更（M-Minor）** | 时间表微调、培训安排调整 | 团队 / Stream | 周会通报 |

### §1.1.3 变更管理的 5 大输出物

| 输出物 | 用途 | 维护方 |
| --- | --- | --- |
| **干系人登记册** | 识别 + 分级 + 诉求 | PMO-M |
| **沟通计划主线** | 时间 × 干系人 × 内容 × 渠道 | PMO-M |
| **公告模板库** | 12+ 场景的公告模板 | PMO-M + CS |
| **反馈管理表** | 收集 + 分发 + 关闭 | CS + PMO-M |
| **变更控制日志** | 所有变更的记录 + 审批 | PMO-M |

### §1.2.5 干系人变更管理

- **新增干系人**：PMO-M 提交 → PMO-D 审批（24h 内）→ 更新登记册；
- **退出干系人**：PMO-M 评估 → 通知 → 保留信息 ≥ 1 年（合规）；
- **诉求变化**：每月审视 → 调整沟通计划；
- **冲突识别**：当 2 个干系人诉求冲突时，PMO-D 仲裁。

## §1.5 沟通渠道（Communication Channels）

> 渠道选择原则：**触达率 × 时效性 × 正式度 × 可追溯**。同一信息可多渠道冗余发布，但需保证口径一致。

### §1.5.1 渠道矩阵

| 渠道 | 触达率 | 时效性 | 正式度 | 可追溯 | 主要用途 |
| --- | --- | --- | --- | --- | --- |
| **现场会议** | 100%（在场） | 即时 | 🟢 高 | 会议纪要 | 启动会、决策门、复盘 |
| **企业 IM（飞书/钉钉/企微）** | ≥ 95% | 即时~分钟级 | 🟡 中 | 永久 | 实时通报、群通知 |
| **邮件** | ≥ 90% | 小时级 | 🟢 高 | 永久 | 正式公告、决策门决议 |
| **LMS 培训系统** | 100%（分配） | 异步 | 🟢 高 | 完成率 + 考试 | 培训交付 |
| **内网 / 知识库** | 按需 | 异步 | 🟢 高 | 版本控制 | 文档、手册、FAQ |
| **应用内公告** | 100%（登录用户） | 即时 | 🟡 中 | 后台日志 | 上线日公告、变更提示 |

### §1.6.1 公告模板设计原则（5 段结构）

```
┌─────────────────────────────────────┐
│ 1. 标题       (≤ 20 字 + Emoji)     │
│ 2. 一句话摘要 (≤ 80 字)            │
│ 3. 关键信息   (What/When/Why)       │
│ 4. 行动要求   (To-Do)               │
│ 5. 反馈渠道   (Feedback)            │
└─────────────────────────────────────┘
```

| 原则 | 释义 |
| --- | --- |
| **短而清晰** | 一段话讲完核心，复杂信息用"详情见链接" |

| **可追溯** | 必须含版本号、发布时间、Owner |

## §1.8 变更控制（Change Control）

> 上线期的"变更"指任何影响上线计划、时间表、范围、干系人、风险的变化。
> 目的：**任何变更都可追溯、可审批、可回退**。

### §1.8.1 变更分类（3 级）

| 级别 | 触发 | 影响范围 | 审批权 | 审批 SLA |

| **L3 微小变更** | 时间表微调、文档勘误、Owner 变更 | 团队 / Stream | **PMO-M** | ≤ 72h |

# §2 培训与采纳（Training & Adoption）

> 让"会用、愿用、常用"：把"功能上线"转化为"用户行为改变"。
> 核心目标：**关键用户培训完成率 ≥ 90% + 关键流程使用率 ≥ 60% + NPS ≥ 30**。

## §2.1 培训总览

### §2.1.1 三大目标

| 目标 | 描述 | 指标 |
| --- | --- | --- |
| **会用（Know）** | 用户掌握核心功能操作 | 培训完成率 ≥ 90%，认证通过率 ≥ 80% |
| **愿用（Want）** | 用户主动使用而非绕道 | 关键流程使用率 ≥ 60% |
| **常用（Use）** | 用户形成日常习惯 | T+7 关键用户 DAU ≥ 60%，T+30 DAU ≥ 75% |

### §2.1.2 三大原则

| 原则 | 释义 |
| --- | --- |
| **按角色** | 不同角色不同课程（不搞"一刀切"大讲座） |
| **按场景** | 每个功能配合业务场景演示（不只讲功能） |
| **按节奏** | T-9 试点 + T-3 全员 + T+0 现场 + T+1 答疑（持续赋能） |

### §2.1.3 三大交付物

| **采纳度跟踪** | DAU + 关键流程 + NPS | TR-L + PMO-M |

### §2.9.6 培训 ROI 计算

> 培训投资回报率（ROI）=（业务收益 − 培训成本）/ 培训成本

#### §2.9.6.1 成本组成

| 成本 | 金额（估） |
| --- | --- |
| 培训预算 | 50 万 |
| 内部讲师时间 | 30 万（8 名 × 0.5 FTE） |
| LMS / 沙箱 | 10 万 |
| 学员工时损失 | 100 万（11,000 人 × 8h × 100 元/h） |
| **总成本** | **~190 万** |

#### §2.9.6.2 业务收益（年化）

| 收益 | 金额（估） |
| --- | --- |
| 项目治理成熟度提升（减少延期） | 500 万 |
| 风险提前识别（避免损失） | 300 万 |
| 工时合规（减少加班） | 200 万 |
| 跨 BU 协作效率提升 | 200 万 |
| 报表自动化（减少人工） | 100 万 |
| **总收益** | **~1,300 万** |

#### §2.9.6.3 ROI

```
ROI = (1,300 - 190) / 190 ≈ 5.8x
```

> **培训 ROI ≥ 5x** 视为成功。
