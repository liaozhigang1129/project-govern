### 3.1 D1 · AI 模型形态

| 字段 | 内容 |
|---|---|
| **决策项** | v5 AI 预测 / 智能推荐 / NLP 报告,采用哪种 AI 模型? |
| **采纳选项** | **A. 集成第三方**(阿里通义 / 百度文心) |
| **替代选项** | B. 自研 ML(已就位 `models/milestone_lgbm_v1.pkl`,沿用) / C. 混合(自研 + 第三方) |
| **决策依据** | 1. 通义/文心国内合规 + 2. 自研 ML 预测能力有限 + 3. NLP 报告本期不做 |
| **关键风险** | 第三方 LLM 数据出境合规(R-M7-05) |
| **拍板人** | Sponsor |

**讨论要点**:
- 自研 ML 只能做"数值预测"(已就位),不能做"语义理解" / "智能推荐"
- 第三方 LLM 是否要做 PII 数据脱敏?(推荐:是,前置脱敏)
- 数据出境合规如何规避?(推荐:仅用国内 LLM,不通 OpenAI)

**预期结论**:**A 采纳**。

### 3.2 D2 · AI 预测上线策略

| 字段 | 内容 |
|---|---|
| **决策项** | ML 模型如何平滑上线? |
| **采纳选项** | **A. 影子模式 4 周 → 灰度 → 全量** |
| **替代选项** | B. 直接全量上线 / C. A/B 测试 50/50 |
| **决策依据** | 风险可控、可回滚、可解释 |
| **关键门禁** | 影子模式 4 周后准确率 ≥ 85% 才灰度 |
| **拍板人** | Sponsor |

**讨论要点**:
- 影子模式:ML 模型后台运行,不影响用户决策,仅记录"如果上线会怎么建议"
- 灰度:10% → 50% → 100%(SRE 流量控制)
- 准确率 85% 阈值是否合理?(推荐:85% 是基线,可下调到 80% 但需要 Architect 复核)

**预期结论**:**A 采纳**。

### 3.3 D3 · 移动 App 形态(关键决策)

| 字段 | 内容 |
|---|---|
| **决策项** | 移动端工时填报,采用什么技术形态? |
| **采纳选项** | **A. Web H5 + 响应式(本期)**,B. Hybrid(Ionic/Cordova),C. Native(iOS+Android) |
| **替代选项** | B / C(本期不做) |
| **决策依据** | 工时填报低频高延展场景,H5 性能已满足(iPhone 14 Pro LCP < 2s) |
| **节省工作量** | vs B 节省 5 周,vs C 节省 13 周 |
| **拍板人** | Sponsor(关键决策,讨论时间可放宽到 8 min) |

**讨论要点**:
- 草案原决策是 Hybrid + PWA,本期进一步降级到 H5,理由是 App Store 上架 + 审核 2-4 周延后
- H5 性能限制:无系统级 PUSH、无后台运行(影响"周一提醒"功能)
- "周一提醒"如何用 H5 实现?方案:复用 IM 通道(钉钉/飞书 webhook) + 浏览器 Notification API
- 价值验证后再决定 v5.1 是否原生

**预期结论**:**A 采纳**。

### 3.4 D4 · 报表/导出实现路径

| 字段 | 内容 |
|---|---|
| **决策项** | 报表 / BI / 4 格式导出,采用自研还是第三方? |
| **采纳选项** | **A. 后端聚合 API + 前端 ECharts + 后端导出 4 格式**(PDF/Excel/CSV/PNG) |
| **替代选项** | B. 嵌入第三方 BI(Tableau/Power BI/帆软) |
| **决策依据** | 1. ECharts + POI 已就位,扩展成本低 + 2. 第三方 BI 数据出境冲突公司合规 + 3. 自研可控性高 |
| **成本对比** | A: 6 周 / B: 年费 50w+ + 3 周集成 |
| **拍板人** | Sponsor |

**讨论要点**:
- 4 格式导出的 PDF 用 OpenPDF + Thymeleaf,Excel 用 POI SXSSF 流式,CSV 用 Commons CSV,PNG 用 Playwright
- PNG 导出需要 Chromium,CI 镜像需预装(已识别为 R-M7-03-02)
- 第三方 BI 在国内合规要求(数据出境)与公司政策冲突,即使预算允许也不推荐

**预期结论**:**A 采纳**。

### 3.5 D5 · 数据集查询策略

| 字段 | 内容 |
|---|---|
| **决策项** | 报表数据查询采用什么策略? |
| **采纳选项** | **A. 预聚合 + 物化视图**,B. 实时跨表 JOIN |
| **替代选项** | B(本期不采纳) |
| **决策依据** | 数据量增长后性能可控;SQL 性能风险(R-M7-02) |
| **实现路径** | `DatasetService` 优先 `report_snapshot` → 回退 `dataset.sql_template` |
| **拍板人** | Sponsor(技术决策,架构师可代为陈述) |

**讨论要点**:
- 物化数据每天 01:00 cron 重建(`@Scheduled cron="0 0 1 * * *"`)
- 实时跨表 JOIN 复杂度随数据量指数级增长,生产事故风险高
- 物化视图牺牲"实时性"换取"性能稳定",业务可接受(报表非实时场景)

**预期结论**:**A 采纳**。

### 3.6 D6 · 订阅分发策略

| 字段 | 内容 |
|---|---|
| **决策项** | 报表订阅分发采用哪些通道? |
| **采纳选项** | **A. Email + IM + 链接分享**(3 通道并行) |
| **替代选项** | B. 仅 Email / C. 仅 IM |
| **决策依据** | 覆盖 PMO / PM / 财务 / 部门负责人 不同角色偏好 |
| **实现细节** | 失败 3 次指数退避(1s/5s/25s) |
| **拍板人** | Sponsor |

**讨论要点**:
- IM 通道:钉钉 + 飞书 + 企业��信(已有 `ImHttpClient` 复用,见 [STATUS.md §1 M6 阶段](../STATUS.md))
- 链接分享:含水印 + TTL 24h(D7 安全)
- 失败重试:3 次指数退避后入"通知失败队列",人工处理

**预期结论**:**A 采纳**。

### 3.7 D7 · 数据安全策略

| 字段 | 内容 |
|---|---|
| **决策项** | 报表导出 / 链接分享 / 订阅产物的安全策略? |
| **采纳选项** | **加密 URL + 用户水印 + TTL 24h** |
| **替代选项** | 永久链接 / 无水印(均不采纳) |
| **决策依据** | 1. 财务 / 薪酬 / 战略数据敏感 + 2. 离职人员不应能访问历史导出 |
| **实现细节** | 见 [WP-M7-03 plan §7](../plans/2026-08-11-wp-m7-03-reporting-export.md#7-d7-数据安全导出加密--水印--ttl-24h) |
| **拍板人** | Sponsor(安全/合规必到) |

**讨论要点**:
- 加密 URL:UUID task_id,不暴露真实 ID
- 用户水印:PDF/PNG 模板嵌入 `${userId} · ${now}`(半透明,无法 PS 去除)
- TTL 24h:订阅产物 / 7d:主动导出(见 [WP-M7-03 §2.2](../plans/2026-08-11-wp-m7-03-reporting-export.md#22-配置applicationyml))

**预期结论**:**A 采纳**。

### 3.8 D8 · 阶段验收门禁

| 字段 | 内容 |
|---|---|
| **决策项** | v5 实施期间,新增哪些专项门禁? |
| **采纳选项** | **6 项 v5 专项门禁**(角色仪表盘覆盖 / 报表模板 / 导出 SLA / H5 性能 / H5 A11y / 数据质量看板) |
| **替代选项** | 仅沿用 v4 门禁(不推荐,见 plan §6 R-M7-02 R-M7-03) |
| **决策依据** | v5 引入新能力(报表 / 移动 / AI 看板),需新门禁量化追踪 |
| **拍板人** | Sponsor(技术决策,QA 可代为陈述) |

**6 项门禁清单**:

| 门禁 | 阈值 | 评审 |
|---|---|---|
| 角色仪表盘覆盖率 | 8 角色 × 默认 dashboard | PMO |
| 报表模板落地数 | ≥ 5 类(状态 / EVM / 资源 / 风险 / 预算) | PMO |
| 导出 SLA | 异步任务 < 60s 完成 | SRE |
| H5 性能 | LCP < 2.5s / FID < 100ms | QA |
| H5 A11y | axe-core 通过(0 critical / 0 serious) | QA |
| 数据质量看板 3 指标 | 完整率 / 准确率 / 时效性 可视化 | PMO |

**讨论要点**:
- H5 性能门禁(Web Vitals)如何监控?方案:`web-vitals` npm 包 + 后端 `metric_event` 表 + 采样 10%
- A11y 门禁:`@axe-core/playwright` CI 集成
- 数据质量门禁:3 指标(完整率/准确率/时效性)如何定义?见 [WP-M7-04 plan §4.1](../plans/2026-08-11-wp-m7-04-ai-dashboard.md#41-3-项核心指标)

**预期结论**:**A 采纳**。
