# ADR 004 · IM 平台回调接入推迟到 v5

> **状态**:accepted(2026-08-07)
> **决策驱动**:WP-M6-03 spike 报告
> **推翻路径**:若 v5 立项重新评估后认为 ROI 高,可启动 ADR 005 推翻本决策

---

## 1. 背景

M6 范围(IM 通知多通道)原本包含"三平台 IM 卡片回调(一键审批)"能力。WP-M6-03 spike 调研后,产出了 [`docs/analysis/2026-08-07-im-oauth-decision-proposal.md`](../analysis/2026-08-07-im-oauth-decision-proposal.md),结论是:

- 三平台 OAuth 流程差异较小(都是标准 OAuth 2.0)
- 卡片回调能力差异较大(签名算法 / 卡片类型 / 回调机制三平台各异)
- 实现成本:**17 人天 ≈ 3.5 周**(单兵全职)
- 前置依赖:**公网 HTTPS 域名 + 国内备案**(7-15 天流程)
- 长期维护:三平台 API 变更需跟进

## 2. 决策

**本期(M6)不做 IM 卡片回调接入,推迟到 v5 立项时一并评估。**

具体动作:
1. 关闭 WP-M6-03 spike 工作包(状态:completed,仅评估)
2. 关闭 STATUS.md §4 风险 R-002(原"IM 平台 OAuth 工作量未评估")
3. 新增风险 R-018(v5 立项拖延)+ R-019(用户反馈)
4. M6 范围调整为:三平台单向通知 + 用户 IM 绑定 + Web 内审批(维持原计划)
5. v5 立项时(预计 2026-Q4)把"卡片回调 + AI 智能审批 + 移动端 SDK"作为一组 spike 评估

## 3. 决策理由

### 3.1 为什么不选 A(本期做)

| 因素 | 影响 |
|---|---|
| 工作量 17 人天 | M6 门禁延期 4 周(08-28 → 09-25) |
| 公网域名备案 | 关键路径,7-15 天不可控 |
| 5s 响应窗口 | 架构压力,业务异步化改造 |
| 长期维护 | 三平台政策变更风险(API 废弃/收费) |
| **ROI** | 17 人天换"卡片一键审批"价值不显著(用户当前 Web 审批已可用) |

### 3.2 为什么不选 C(永久不做)

- IM 通道沦为"单向通知",与市面主流 PMO 工具拉开差距
- v5 必然涉及移动端,届时 IM 回调会更迫切
- 永久砍掉 = 关闭可能性,不利于迭代

### 3.3 为什么选 B(本期不动,v5 一并评估) ⭐

- 本期按 M6 既有范围交付,不延期
- 17 人天 + 公网域名/备案一并推到 v5,届时技术栈更成熟
- v5 一起评估可与 **AI 智能审批** / **移动端 SDK** 三件套联动,价值更大
- 决策正式化(ADR 004),避免反复讨论

## 4. 后果

### 4.1 正面
- ✅ M6 门禁维持 2026-08-28
- ✅ 本期无延期
- ✅ 资源投入更聚焦(已有 COST_DIFF / 6 类规则 + 调度器)
- ✅ 触发 v5 立项实质推进

### 4.2 负面
- ❌ 短期内移动端无"卡片一键审批"能力
- ❌ 用户期望管理:M6 通知能力升级(覆盖三通道)但交互未升级

## 5. 推翻条件

满足以下任一条件可启动 ADR 005 推翻:

1. **PMO 重大需求**:客户/领导明确要求"卡片审批"
2. **公网域名前置就绪**:基础设施提前准备好,实现成本 < 10 人天
3. **v5 立项失败**:v5 范围被砍,需要把 IM 回调拉回 v4+
