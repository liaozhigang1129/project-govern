# 报表与数据分析(Reporting)

> 本 Spec 定义报表、仪表盘、自助 BI 与数据质量治理的**业务范围与功能边界**。
> 不回答"接口字段长啥样"(那是 [reporting-api.md](reporting-api.md)),
> 不回答"如何实现"(那是 M7 工作包下的 plan)。

---

## 1. 角色化仪表盘(8 角色 × 9 内容域)

| 角色 | 仪表盘内容 |
| --- | --- |
| PMO 总监 | 组合全景、投资分布、RAG、战略地图、KPI 达成率、Top 风险 |
| PMO 经理 | 项目集健康度、阶段审计、PM 排名、资源热点 |
| 项目经理(PM) | 我的项目、待办、风险、里程碑、Sprint 燃尽、团队利用率 |
| 部门负责人 | 部门资源利用率、部门项目 RAG、关键人风险 |
| 资源经理 | 资源冲突、未来 4 周空缺、人员空档 |
| 业务负责人 | 收益达成、ROI、关键里程碑、变更概览 |
| 财务 | 预算 vs 实际、应收应付、合同回款 |
| 任务执行人 | 我的任务、Sprint、待填工时、被@/评论 |
| 审计 | 操作日志、变更日志、敏感数据访问 |

> 实现策略:角色 → dashboard_id 映射表(`system_config`);首登绑定默认 dashboard;
> 用户可自建 personal dashboard;role default 由 PMO_ADMIN 配置。

## 2. 报表类型(9 大类)

| 类别 | 描述 | 主要消费者 |
| --- | --- | --- |
| **状态报告** | 周/月/季度项目状态汇总 | PMO / PM |
| **挣值报告(EVM)** | PV/EV/AC/SPI/CPI/TCPI/EAC/VAC | PMO / 财务 |
| **资源报表** | 利用率热力、人员借调、未来可用 | 资源经理 / PMO |
| **风险热力** | P×I 矩阵 + 时间维度 | PMO / 部门负责人 |
| **质量报表** | 缺陷密度、SLA、评审一次通过率 | PMO |
| **预算/成本报表** | 多维(项目/部门/WBS/类别/期间)预算 vs 实际 | 财务 / PMO |
| **组合报表** | 投资、收益、战略对齐 | PMO 总监 / 业务负责人 |
| **人员绩效** | 项目参与度、任务完成率、工时合规(脱敏) | PMO / HR |
| **审计合规报表** | 操作日志、登录、敏感数据访问 | 审计 |

> 实现策略:每类报表对应一个 `report_template` 表(`id, code, name, query_sql_id, format`)
> + 后端调度任务定期物化(`report_snapshot`);前端按 template 渲染。

## 3. 自助分析(BI)

- **可视化配置**:拖拽式(柱/线/饼/散点/桑基/漏斗/甘特/热力)
- **维度/度量**:预置业务语义层(如"项目健康度"、"资源利用率")
- **筛选/钻取/联动**:支持 cross-filter 与 drill-down
- **报表权限**:继承数据权限(行级 + 列级)
- **订阅与分发**:定时邮件、IM 推送、链接分享(含水印)
- **导出**:PDF / Excel / CSV / PNG
- **嵌入式分析**:可嵌入第三方 BI 仪表盘(Tableau / Power BI / 帆软 等)

> 实现策略:BI 用前端组件化封装(ECharts + 后端聚合 API);不直接集成第三方 BI 工具。
> 导出服务见 §4。

---

## 4. 导出格式与服务

| 格式 | 适用场景 | 后端实现 |
| --- | --- | --- |
| **PDF** | 正式报告、合同附件、邮件分发 | OpenPDF / iText + 模板引擎(Thymeleaf) |
| **Excel** | 财务对账、数据二次加工 | Apache POI (sxssf,流式) |
| **CSV** | 数据导入、ETL、大数据量 | 原生 writer,UTF-8 BOM(Excel 兼容) |
| **PNG** | 图表分享、IM 推送 | ECharts server-side render(ECharts node-canvas) |

> **异步导出**:>1000 行 / >5MB 自动转异步(返回 task_id,前端轮询/SSE 完成)
> **同步导出**:≤1000 行 / ≤5MB 同步返回 stream
> **存储**:导出产物存 `report_export` 表 + 对象存储(可对接 MinIO/OSS),保留 7 天

## 5. 数据质量治理

- **必填校验**:关键字段(项目预算、立项预算、里程碑计划日期、工时)前端 + 后端双校验
- **异常检测**:超时未更新(项目 7 天无动态)、孤儿任务(无 project_id)、超载人员(连续 4 周 > 50h/周)
- **数据治理看板**:完整率、准确率、时效性 3 项指标
- **异常处理**:自动建 data_quality_alert → 通知 PMO_ADMIN

> 实现策略:数据质量任务挂载在已有的 [Alert 引擎](../specs/api-contract.md) 上,
> 不新建独立引擎。

- 数据治理看板 3 项指标可视化

## 8. 风险登记

- **R-REP-01**:第三方 BI 嵌入性能风险 → MVP 不嵌入,仅保留导出对接
- **R-REP-02**:导出大数据量内存风险 → 必须流式 + 异步任务,禁止一次性 load
- **R-REP-03**:报表 SQL 性能风险 → 必须预��合 + 物化,禁止实时跨表 JOIN
